# ADR-005:fan-out 深度研究 + 长期记忆(旗舰体验)

- **状态**:已采纳(M4;耐久子任务 fan-out 与语义记忆待后续)
- **日期**:2026-07-10

## 背景

M4 交付旗舰:研究规划 → fan-out 子问题 → 多源采集 → 句级引用 + 独立核实 → 报告分享页;长期记忆(总纲 §7)。句级引用 + 红黄绿核实在 M2 已实现,M4 升级为课题分解 + 并行取证 + 记忆。

## 决策

1. **fan-out 用进程内并行**:plan 步用便宜模型把课题拆成 2–4 个子问题,`Promise.all` 并行检索(各子问题走 web_search 工具),汇成去重来源池,再由强模型跨子问题综合、独立模型核实。每个子问题在事件流独立可见(玻璃盒展示 fan-out 树)。
   - **取舍**:没用耐久子任务(parent/child + `waiting_child` park/resume)。理由:进程内并行足以展示"课题分解 + 并行多源"这一 M4 核心,且完全可确定性测试(脚本网关);耐久子任务是更深的"多 Agent 协同"版本,依赖尚未落地的 park/resume,留作后续增量。schema 的 `parent_task_id` 已为它预留。
2. **长期记忆复用 M3 嵌入**:owner 隔离 + 写入去重(相似度阈值)+ 召回相关性下限 + 按 owner 容量上限(最久未用淘汰),声明式/程序性双记忆。研究完成后把绿标结论沉淀为记忆,下次相关课题在 plan 步召回(`memory.recall` 事件可见)。
3. **召回下限与 embedder 绑定**:本地 bigram 词法嵌入下,同域改写相似度约 0.2、纯噪声约 0,故默认 floor 0.15;语义嵌入(bge-m3)改写相似度 ~0.6,应提到 ~0.35–0.5。经 `MEMORY_RECALL_FLOOR` 覆盖。
4. **报告分享页公开可访问**:`/report/[id]` 只读渲染任务结果(子问题 + 论断红黄绿 + 引用锚点跳转来源 + 摘要),无需登录(访客只看回放,总纲 §3)。

## 后果

- 端到端验证:研究"耐久队列如何不丢任务"→ 拆 4 子问题 → 5 来源 → 19 论断全绿 → 沉淀 3 条记忆;后续"worker 崩溃怎么恢复"在 plan 步召回 3 条记忆;报告页公开渲染。
- **诚实边界**:① fan-out 是进程内并行,非耐久子任务;② 记忆召回质量受词法嵌入限制(floor 需随 embedder 调),换 bge-m3 后召回更准、floor 上调;③ 无认证,owner 暂用 createdBy/anonymous,M5 接登录后换真实用户隔离。
