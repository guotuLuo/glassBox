# ADR-007:评测门禁 + 公开 /evals(评测与治理)

- **状态**:已采纳(M5)
- **日期**:2026-07-13

## 背景

总纲 §3.4 差异化:确定性 agent benchmark 卡合并 + 公开 `/evals` 展示分数曲线,回答"你怎么知道它变好了"。前一轮讨论评价 agent 质量时确认:目前只有"我肉眼看几次跑"+ 一个客观信号,缺系统化、可回归、能卡 CI 的评测。本 ADR 把它建成。

## 决策

两条评测线,定位不同:

1. **确定性 RAG 召回(CI 门禁)**:本地 bigram 嵌入完全确定 → 同语料同题集永远同分,适合回归门禁。`run-rag-eval` CLI 摄取演示语料 → 对标注集算 hit@3/@5 + MRR(vector/fts/hybrid 三路)→ 入库 `rag_eval_runs` → 混合 hit@5 低于 `GATE_HIT5`(默认 0.6)则退出码 1。CI 加 `eval-gate` job(pg service 容器 + migrate + eval:rag),分数回归即卡合并。免费、可复现、不调 LLM。

2. **研究忠实度(质量信号)**:聚合真实研究任务的核实器红黄绿裁定 → 绿比。这是**已经产出**的信号(每次研究都跑独立核实),不额外花钱,且会随来源质量波动 —— 是真实的质量曲线。

`/evals` 公开页(无需登录)同时展示两者:召回门禁(护栏,当前 1.0)+ 忠实度(当前 42% 绿,按研究任务列出)。

## 后果

- "分数卡分"真实运转:CI eval-gate job 每次 push 跑评测,回归即红。
- 公开可演示:`/evals` 回答"你怎么知道它变好了"——召回有门禁曲线,忠实度有真实分布。
- **诚实边界**:① 确定性召回在当前小语料上是 1.0(护栏,不代表检索完美,换大语料/语义嵌入才有区分度);② 忠实度测"论断是否被来源支撑",非"答案对不对",绿比偏低主因是联网抓取的来源质量,不是推理错;③ CI 门禁跑在临时容器,分数入临时库 —— 跨版本持久曲线需部署后写生产库(现 /evals 读本地库);④ LLM judge 夜跑(端到端质量打分)与多租户/配额/限流/注入防御是 M5 剩余项。
