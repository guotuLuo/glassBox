# ADR-006:联网研究——中转发现 URL + 自建抓取(保留玻璃盒)

- **状态**:已采纳(M4 增量)
- **日期**:2026-07-10

## 背景

研究 agent 此前只能检索已摄取的私有语料库,问知识库外的任意话题(如"天空为什么是蓝色")会因无来源而诚实拒答。需要联网搜索。约束:无独立搜索 API key(unifiedsearch 绑公司凭证、博查/Tavily 未配);仅有用户自购的 OpenAI 兼容中转(逆向 Codex),其 `/responses` 端点带 `web_search` 工具。

## 决策

**中转只负责"发现 URL",GlassBox 自己抓正文、绑引用、做核实**——用中转的 web_search 拿到相关网页链接,再由 GlassBox 用自建抓取管线读取网页正文,喂进既有的"综合→引用→独立核实"循环。

实测依据:
- 中转的 web_search 能触发真实联网(拿到 NASA/NOAA/PMC 等真实链接);
- 但一旦要求它返回结构化结果它就不搜了、只想"边搜边答"。若直接用它的答案,GlassBox 退化为"贴链接的问答机",丢掉句级引用绑定 + 独立核实这一差异化(总纲 §3)。

因此:`discoverUrls`(web-discover.ts)用自然提问触发搜索、正则抽 URL;`fetchPage`(fetch-page.ts)过 SSRF 防护后抓取,用 @mozilla/readability 抽正文;`createWebResearchTool` 挑与查询最相关的片段作来源。worker 把"联网研究 + 私有知识库"合并成一个 `web_search` 工具(总纲 §0「网页 + 私有文档多源」),对 agent 透明。

## 后果

- 端到端验证:"天空为什么是蓝色"→ 拆 4 子问题 → 抓 NASA/NOAA 真实网页 → 带引用报告 + 红黄绿核实;来源同时含私有 kb:// 与公网 https://。玻璃盒完整:引用绑定的是 GlassBox 抓到的真实正文,不是模型黑盒答案。
- 核实层如常严格:即使答案大方向对,若抓到的具体网页不能严格支撑某条论断,核实器照样标黄/红——这正是"敢被审计"。
- **诚实边界**:① URL 发现质量随中转波动(有时找到的不是最佳解释页);② 片段相关性用 bigram 窗口打分,非 chunk 级检索,可再优化;③ 抓取会失败(超时/反爬/大陆访问外网不稳),失败当一等公民(跳过并在事件流可见);④ Node fetch 不认 HTTP_PROXY,开发机需 `OUTBOUND_PROXY`,生产服务器直连;⑤ 仍依赖逆向中转做发现,博查/Tavily key 到位后可替换为更干净可靠的发现源(接口位已抽象)。
